## LLM 호출 테스트

메이플스토리 캐시샵의 가상 고객센터를 소재로 실험했습니다. 상담 시점은 2024년 1월 10일로 가정했으며, 실제 결제 조회나 고객센터 연결은 수행하지 않았습니다.

**공통 호출 설정**

- 모델: `gpt-6-luna`
- API / SDK: OpenAI Responses API / OpenAI Python SDK `3.41.0`
- 추론 설정: `reasoning={"effort": "none"}`
- 출력 토큰 상한: `max_output_tokens=2000`
- 저장 옵션: `store=False`
- 자동 재시도: `0`, 요청 제한 시간: `60초`
- 이전 질문·응답, `previous_response_id`, `conversation`을 다음 요청에 전달하지 않았습니다.
- 실행마다 새 JSON 파일을 생성하고, 질문·설정·반복 횟수·원본 응답·오류를 호출마다 저장했습니다. 파일에 기록을 누적하는 것과 모델에 대화 이력을 보내는 것은 별개입니다.


### [ 실험 1 : 같은 질문을 반복하면 답변도 같을까? ]

**& 목적**

같은 질문을 동일한 조건으로 반복했을 때, 답변의 표현과 안내 내용이 얼마나 일관되게 나오는지 확인합니다.

**& 실험 방법**

- 모델: `gpt-6-luna`
- 질문 3종을 준비하고, 각 질문을 동일한 문장으로 3회씩 호출했습니다.
- A: “결제했는데 아이템이 안 들어왔어요.”
- B: “블랙 큐브를 결제했는데 아이템이 안 들어왔어요.”
- C: “10분 전에 블랙 큐브를 결제했는데 아이템이 안 들어왔어요.”
- 총 9회 호출했으며, 같은 질문의 반복 사이에는 지시문과 호출 설정을 유지했습니다.
- `temperature`와 `top_p`는 명시적으로 전달하지 않았습니다.

**& 내 예상**

같은 질문이더라도 글자 하나까지 정확히 같은 답변이 나오지는 않겠지만, 맥락은 비슷하게 나올 것으로 예상했습니다.

### [ 실험 2 : Temperature와 Top-p를 바꾸면 답변과 판단도 달라질까? ]

**& 목적**

같은 질문에서 Temperature와 Top-p를 각각 변경했을 때, 요청 분류와 다음 조치가 얼마나 일관되게 유지되는지 확인합니다. 고객에게 전달하는 답변의 표현과 안내 내용도 함께 비교합니다.

**& 설정 설명**

Temperature와 Top-p는 모델이 다음 토큰을 선택하는 방식을 조절하는 설정입니다. Temperature는 후보들의 확률 분포를 조절하고, Top-p는 누적 확률을 기준으로 후보 범위를 제한합니다. 값을 낮추면 가능성이 높은 표현에 집중하고 높이면 다양한 표현이 나올 가능성이 커지지만, 답변의 정확성이나 동일성을 보장하지는 않습니다.

**& 실험 방법**

- 모델: `gpt-6-luna`
- 메이플스토리 캐시샵의 가상 고객센터 상황으로 진행했습니다.
- Pydantic과 구조화 출력을 사용해 `request_type`(요청 유형), `urgency`(긴급도), `customer_reply`(고객에게 답변할 내용), `next_action`(다음 조치)의 네 필드를 받았습니다.
- `customer_reply`는 한국어 존댓말로 1~2문장, 나머지 필드는 정해진 상수 중 하나를 선택하도록 했습니다. 문장 수와 내용의 적절성은 실제 응답을 읽으며 확인했습니다.
- Temperature 실험은 `top_p=1.0`으로 고정하고, `temperature`를 `0.0`, `0.7`, `1.3`으로 변경했습니다.
- Top-p 실험은 `temperature=1.0`으로 고정하고, `top_p`를 `0.1`, `0.5`, `1.0`으로 변경했습니다.
- 각 실험에서 질문·지시문·분류 기준·출력 스키마와 나머지 호출 설정을 유지했습니다. 공통 지시문에는 특정 상품명을 넣지 않았습니다.
- 질문별로 각 설정에서 3회씩 호출했습니다. 두 질문에 각각 18회, 총 36회 호출했으며 이전 질문이나 응답은 다음 요청에 전달하지 않았습니다.

구체적인 분류 기준과 스키마는 [main2.py](./main2.py)에 기록했습니다.

**& 내 예상**

Temperature를 낮추고 Top-p를 높이면 `customer_reply`의 표현과 안내 내용이 더 일관되게 나오고, 분류 필드도 같은 값으로 유지될 것으로 예상했습니다.

설정값을 반대로 바꾸면 답변의 표현이 다양해지고, 분류 필드의 선택에도 차이가 나타날 것으로 예상했습니다.

**& 질문 구성**

먼저 상품명과 구매 후 경과 시간이 구체적인 정형적 질문으로 진행했습니다.

> Q : 10분 전에 블랙 큐브를 결제했는데 아이템이 안 들어왔어요.

이 질문에서는 모든 설정에서 요청 유형·긴급도·다음 조치가 정한 기준에 맞게 동일하게 나왔고, 고객 답변의 표현과 세부 안내에는 차이가 있었습니다.

이후 실제 사용자가 입력할 법한 짧은 구어체로 질문을 바꿔, 같은 설정 조합으로 추가 실험했습니다.

**& 정리**

- 총 36회 모두 정상 완료되었고, 오류나 중간에 끊긴 응답 없이 Pydantic 구조 검증을 통과했습니다.
- 정형적 질문에서는 모든 설정에서 세 분류 필드가 기준에 맞게 동일하게 유지되었습니다. 구어체 질문에서는 `request_type`과 `urgency`는 유지됐지만, `next_action`은 달라졌습니다.
- 낮은 설정에서도 답변과 조치가 달라졌으며, 이번 조건별 3회 실험에서는 설정값이 낮을수록 결과가 더 일관된다는 뚜렷한 경향을 확인하지 못했습니다.
- 구조 검증을 통과하더라도 조치 판단의 적절성은 별도로 확인해야 하며, 일부 응답에서는 확인 방법 안내와 추가 정보 요청의 경계가 겹쳤습니다.
- 두 질문은 말투뿐 아니라 상품명과 시간의 구체성도 달랐으므로, 결과 차이를 구어체 사용만의 영향으로 단정할 수는 없습니다.

⇒ 요청 유형과 긴급도는 유지됐지만 구어체 질문에서는 다음 조치가 달라졌으며, 설정값을 낮출수록 결과가 더 일관된다는 뚜렷한 경향은 확인하지 못했습니다.
