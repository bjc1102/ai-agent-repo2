# 공모 증권신고서의 정정 전후 비교를 위한 RAG 실습

[RAG 이론정리](이론정리.md)

## 1. RAG 실습 주제

IPO 신규 상장을 위한 증권신고서 PDF로, 질문과 관련된 내용을 검색하고 그 근거를 바탕으로 답변하는 기본 RAG를 구현했습니다.

## 2. 사용 자료와 선정 이유

| 항목 | 내용 |
|---|---|
| 자료 | `[동원파츠][정정]증권신고서(지분증권)(2026.10.30).pdf` |
| 원본 | [PDF 파일](<docs/[동원파츠][정정]증권신고서(지분증권)(2026.10.30).pdf>) |
| 출처 | [금융감독원 전자공시시스템(DART)](https://dart2.fss.or.kr/dsab007/main.do)에서 다운로드했습니다. |

| 주요 내용 | 공모가격 확정, 공모 조건 및 자금 사용 계획 등의 정정 전후 내용 |
| 선정 이유 | 공모주 청약 판단에 필요한 정보를 문서에서 찾는 과정을 실습하고, 금액·단위·정정 시점을 구분해 답할 수 있는지 확인하기 위해 선택했습니다. |


## 3. 구현 구성과 설정

### 구성 방식과 선택 이유

간단한 환경에서 처리 단계를 하나씩 실행하고 확인하기 위해 **로컬 Chroma를 직접 설치하는 방식**을 선택했습니다.
Python 코드에서 OpenAI SDK와 Chroma를 직접 호출해 흐름을 연결했습니다. 입력 청크, 검색 결과, 모델에 전달하는 컨텍스트를 직접 확인하기 쉬운 구성을 우선했습니다.

| 담당 | 역할 |
|---|---|
| 직접 작성한 Python 코드 | 정정 구간 구분, 청크 분할, 메타데이터 생성, API·DB 호출 연결, 검색 조건 설정, 프롬프트 구성, 실행 기록 저장 |
| pypdf | PDF 텍스트 추출 |
| OpenAI API | 문서·질문의 임베딩 생성과 검색 근거를 이용한 최종 답변 생성 |
| Chroma | 본문·메타데이터·벡터 저장 및 벡터 검색 인덱스 관리 |

### 처리 흐름

**최초 인덱싱**

```text
PDF → 텍스트 추출 → 정정 전후 구간 구분 → 청크 분할
    → OpenAI 임베딩 생성 → Chroma에 본문·메타데이터·벡터 저장
```

**질문 처리**

```text
질문 → 질문 임베딩 생성 → 정정 전 3개·정정 후 3개 검색
     → 검색 본문을 컨텍스트로 전달 → 답변 생성 → JSON 기록 저장
```

### 실제 사용 설정

| 항목 | 설정 |
|---|---|
| 실행 환경 | macOS, Python 가상환경 `.venv` |
| 벡터 저장소 | Chroma `1.5.9`, `PersistentClient` |
| 저장 경로 | 프로젝트 폴더의 `chroma_db/` |
| 컬렉션 | `dongwon_20261030_v1` |
| 임베딩 모델 | `text-embedding-3-small` |
| 벡터 차원 | 1,536 |
| 인덱싱 배치 | 청크 32개씩 임베딩 요청 |
| 답변 모델 | `gpt-5.4-mini-2026-03-17` |
| 답변 설정 | Responses API, `reasoning.effort="none"`, `max_output_tokens=2000` |
| 청크 크기 | 1,200자 기준, 줄 경계에서 분할 |
| 청크 겹침 | 마지막 온전한 줄들을 최대 200자까지 재사용합니다. 실제 겹침 길이는 청크마다 다릅니다. |
| 분할 경계 | 페이지와 정정 구간을 넘지 않도록 분할 |
| 검색 방식 | Chroma HNSW 인덱스의 코사인 거리 기반 벡터 검색 |
| 검색 조건 | `revision="before"`와 `revision="after"`를 각각 적용 |
| 검색 개수 | 정정 전 3개 + 정정 후 3개, 총 6개 |

- **전처리:** 155개 구간을 325개 청크로 분할했습니다. 정정 전 155개, 정정 후 165개, 요약·안내 5개이며, 검색에는 정정 전후 청크만 사용합니다.
- **저장·검증:** 문서명·페이지·정정 정보 등을 함께 저장하고, 본문·메타데이터·벡터 차원을 검증했습니다.
- **재실행:** 저장된 청크는 건너뛰며, 입력 파일이나 모델 설정이 기존 색인과 다르면 중단합니다.
- **모델 입력:** 질문과 검색 근거만 전달하며, 예상 답변과 참고 페이지는 평가용으로 분리했습니다.
- **답변 원칙:** 정정 전후·단위·계획과 실적을 구분하고, 근거가 부족하면 확인할 수 없다고 안내하도록 구성했습니다.

## 4. 실행 방법

저장소 루트에서 아래 순서로 실행합니다. API 호출 전 `DChanHong` 폴더의 `.env`에 `OPENAI_API_KEY`를 설정합니다.

```bash
cd week-02/DChanHong
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

# 최초 데이터 준비 및 인덱싱
python script/test/check_pdf.py
python script/test/check_sections.py
python script/test/check_chunks.py
python script/test/check_index.py

# 질문 3개 테스트
python main.py
```

환경과 DB가 준비된 경우 가상환경 활성화 후 `python main.py`만 실행합니다. 결과는 `output/rag_runs/<실행시각>/`에 저장됩니다.
