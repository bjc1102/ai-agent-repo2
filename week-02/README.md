# 2주차 과제와 발표 안내

이번 과제는 RAG 조사·정리와 기본 RAG 실습입니다.
다음 수업에서 이해한 내용, 구현 흐름과 대표 실행 결과를 합쳐 5분 이내로 발표해주세요.

## 1. RAG 조사·정리

아래 스탠포드 강의와 1기 3주차 영상을 참고해 RAG를 자신의 말로 정리해주세요.

- RAG는 LLM의 어떤 한계를 보완하나요? 컨텍스트의 중요성과 연결해 설명해주세요.
- 문서 준비 → 검색 → 컨텍스트 구성 → 답변 생성은 어떻게 이어지나요?
- 키워드 기반 검색과 임베딩 기반 검색은 어떻게 다른가요?
- 청킹, 임베딩과 Vector Store는 각각 어떤 역할을 하나요?
- RAG를 적용해도 어떤 문제가 남을 수 있나요?

강의 후반부 연구 사례는 아키텍처와 정보가 흐르는 방식, 어떤 문제를 개선하려는지 중심으로 살펴보세요.
이해되지 않은 부분은 질문으로 남겨주세요.

## 2. 기본 RAG 실습

### 구성 방식 선택

아래 두 방식 중 하나를 선택해 실습해주세요.

- 직접 설치: Chroma, Qdrant 같은 벡터 DB를 로컬이나 서버에 설치하고 문서 처리, 임베딩, 검색과 답변 생성을 연결합니다.
- 관리형 구성: Amazon Bedrock Knowledge Bases 같은 관리형 서비스를 사용해 문서 수집, 검색과 답변 생성 흐름을 구성합니다.

선택한 방식과 이유를 기록하고, 직접 구현한 부분과 서비스가 처리하는 부분을 설명해주세요.

### 실습 데이터 선택

가급적 관심 있는 주제의 공개 데이터를 직접 찾아 사용해주세요.
- 고객센터 FAQ, 공개 PDF, 제품 설명서, 서비스 이용 안내 등 질문의 근거를 찾을 수 있는 자료를 선택하면 됩니다.
- 자료의 제목, 출처와 선택한 이유를 기록하고 PDF는 텍스트가 정상적으로 추출되는지 먼저 확인해주세요.

자료 선택이 어렵다면 아래 예시를 사용해도 됩니다.

- `2024 알기 쉬운 의료급여제도`: 제도 설명과 FAQ, 조건·예외가 포함된 한국어 PDF입니다. 1기 GitHub 저장소에서 PDF를 내려받아 사용할 수 있습니다.
- `FinanceBench`: 기업 공시 PDF와 질문·정답·근거가 제공되는 데이터셋입니다. 공개 샘플은 150문항이며 영문 재무표와 계산 문제가 포함되어 난도가 더 높습니다.

### 구현과 실행

1. 선택한 자료를 불러오거나 서비스에 연결하고, 검색에 사용할 텍스트와 청크를 준비합니다.
2. 질문과 관련된 청크를 검색하도록 구성합니다. 사용한 검색 방식, 청크 설정과 검색 개수를 기록합니다.
3. 검색된 내용을 컨텍스트로 전달해 모델이 답변하도록 연결합니다. 벡터 검색을 사용했다면 임베딩 모델과 저장소도 기록합니다.
4. 질문을 최소 3개 준비해 실행합니다. 문서에 답이 있는 질문과 문서에서 답을 확인할 수 없는 질문을 모두 포함해주세요.
5. 각 질문의 실제 검색 결과와 최종 답변을 문서와 대조합니다. 필요한 근거를 찾았는지, 답변이 그 근거에 맞는지 확인해주세요.
6. 실행 결과에서 확인한 한계나 예상과 달랐던 점을 정리합니다. 구현 중 막힌 부분이 있다면 진행 상황과 함께 남겨주세요.

문서에서 질문의 답을 확인할 수 없다면 정보가 부족하다고 안내하도록 구성해주세요.
언어, 모델, 프레임워크와 실행 환경은 자유롭게 선택할 수 있으며 AI 도구도 활용할 수 있습니다.
선택한 구성의 문서 준비 → 검색 → 답변 생성 흐름과 각 단계의 역할을 설명할 수 있어야 합니다.
