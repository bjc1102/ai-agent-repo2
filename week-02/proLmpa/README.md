# Week-02 RAG 기본 구현

## 1. 선택 방식 및 이유

**직접 설치(Self-hosted)** 방식을 선택했습니다.

| 컴포넌트 | 선택 | 이유 |
|----------|------|------|
| Vector Store | ChromaDB (persistent) | pip 설치만으로 동작, 별도 서버·클라우드 계정 불필요, 인덱스 디스크 저장 |
| 임베딩 모델 | `paraphrase-multilingual-mpnet-base-v2` | 로컬 실행, 한국어 지원, 완전 무료 |
| LLM | Claude claude-sonnet-4-6 (Anthropic API) | 기존 API 키 재사용, 한국어 고품질 답변 |
| PDF 파싱 | pdfplumber | 한국어 PDF 텍스트 추출 안정적 |

외부 벡터 DB 서비스나 별도의 임베딩 API 없이 로컬에서 전 과정이 실행되므로, 비용·네트워크 의존성을 최소화할 수 있습니다.

## 2. 데이터 소개

| 항목 | 내용 |
|------|------|
| 파일명 | `2024 알기 쉬운 의료급여제도.pdf` |
| 출처 | 보건복지부 / 국민건강보험공단 발간 공식 안내 자료 |
| 페이지 수 | 약 40페이지 |
| 내용 요약 | 의료급여 1·2종 구분, 본인부담금, 선택병의원 제도, 정신과 입원 절차, 급여 제외 항목 등 |

한국어 텍스트가 풍부하고 구조적인 내용(표·목록)을 포함해 RAG의 청킹·검색 성능을 평가하기에 적합합니다.

---

## 3. 처리 흐름

```
PDF 파일
   │
   ▼
[1] 문서 로드 (pdfplumber)
   페이지별 텍스트 추출, 빈 페이지 스킵
   │
   ▼
[2] 청킹
   500자 단위 분할, 100자 오버랩
   메타데이터 부착: {source, page, chunk_id}
   │
   ▼
[3] 임베딩 & 인덱싱
   SentenceTransformer 로컬 모델로 배치 인코딩
   ChromaDB PersistentClient로 디스크 저장 (chroma_db/)
   │
   ▼  rag_basic.py 여기까지 실행 ──────────────────────────────┐
                                                               │
[4] 검색 (Retrieval)          ← query.py 는 chroma_db/ 를 로드 │
   쿼리 임베딩 → ChromaDB cosine 유사도 검색                    │
   top_k 청크 반환 (기본 3, --top-k 로 조정 가능)               │
   │                                                           │
   ▼                                                           │
[5] 답변 생성 (Generation)                                      │
   검색된 청크를 컨텍스트로 Claude API 호출                      │
   "문서 내용만 근거로 답변" 시스템 프롬프트                      │
   │                                                           │
   ▼                                                           │
최종 답변 출력 ──────────────────────────────────────────────────┘
```

---

## 4. 주요 설정값

| 파라미터 | 값 | 설명 |
|----------|----|------|
| `CHUNK_SIZE` | 500 | 청크 최대 문자 수 |
| `CHUNK_OVERLAP` | 100 | 인접 청크 간 오버랩 문자 수 |
| `TOP_K` | 3 | 검색에서 반환할 청크 수 |
| `EMBEDDING_MODEL` | `paraphrase-multilingual-mpnet-base-v2` | 로컬 임베딩 모델 |
| `max_tokens` | 1024 | Claude 응답 최대 토큰 |

## 5. 실행 방법

```bash
# 1. 의존성 설치
pip install -r requirements.txt

# 2. 인덱스 빌드 + 테스트 질문 4개 실행 (chroma_db/ 생성)
python rag_basic.py

# 3. 대화형 질의 (rag_basic.py 실행 후 사용 가능)
python query.py

# top_k 조정 예시
python query.py --top-k 5
```

## 8. 한계 및 개선점

| 한계 | 개선 방향 |
|------|-----------|
| 고정 크기 청킹 — 문단 경계 무시 | 의미 단위(문단·항목) 기반 청킹 |
| 단순 cosine 유사도 검색 | BM25 하이브리드 검색 또는 reranker 추가 |
| 단일 PDF 소스 | 여러 문서 동시 인덱싱 및 출처 관리 |
| 임베딩 모델 크기 (768d) | 도메인 특화 fine-tuning 또는 더 큰 모델 사용 |
| PDF 변경 시 전체 재인덱싱 필요 | 청크 단위 증분 업데이트 지원 |
