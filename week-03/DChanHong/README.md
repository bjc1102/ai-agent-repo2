- [LLM Evaluation 이론 정리](./THEORY.md)

## 1. 평가 목적

이번 평가는 2주차에 구축한 동원파츠 정정 증권신고서 RAG가 문서에 근거해 사용자의 질문을 정확하게 해결하는지 확인하는 것을 목적으로 합니다.

증권신고서에는 정정 전후의 정보와 여러 금액·비율·계획이 함께 포함되어 있습니다. 따라서 관련 숫자를 답변하는 것뿐 아니라, 질문이 요구한 시점과 항목을 구분하고 필요한 계산을 정확하게 수행하는 것이 중요합니다. 문서에 없는 정보는 추정하지 않고 확인할 수 없다고 안내해야 합니다.

기존 RAG 구성을 유지한 상태에서 검색 결과와 생성 답변을 나누어 평가합니다. 이를 통해 필요한 근거를 찾지 못한 문제와, 찾은 근거를 답변에 잘못 사용한 문제를 구분하고 우선 개선할 대상을 판단합니다.

또한 자동 평가 결과를 사람의 원문 대조 결과와 비교하여, 평가 지표와 LLM Judge가 실제 답변의 문제를 충분히 포착하는지도 확인합니다.

## 2. RAG의 성공·실패 기준

RAG의 성공 여부는 내용의 정확성, 인용의 적절성, 답변 범위 준수를 기준으로 판단합니다.

| 평가 항목 | 성공 기준 | 실패 사례 |
|---|---|---|
| 내용의 정확성 | 사실·금액·단위·계산이 정확하고, 정정 전후 및 계획과 실적을 구분합니다. | 계산 결과가 틀리거나, 정정 전 정보를 정정 후 정보로 설명하거나, 계획액을 실제 집행액으로 답합니다. |
| 인용의 적절성 | 핵심 주장에 근거를 연결하고, 인용한 청크가 해당 내용을 실제로 뒷받침합니다. | 인용한 청크에 해당 내용이 없거나, 질문에서 요구한 시점과 다른 근거를 사용합니다. |
| 답변 범위 준수 | 답변 가능한 내용은 충분히 설명하고, 확인할 수 없는 내용은 구분하여 안내합니다. | 필요한 내용을 누락하거나, 일부만 답할 수 있는 질문 전체를 거절하거나, 문서에 없는 정보를 만들어냅니다. |

질문의 답변 가능 여부에 따라 기대하는 동작도 구분합니다.

- **답변 가능한 질문:** 필요한 근거를 찾아 질문에서 요구한 내용을 정확하고 충분하게 답변합니다.
- **답변 불가능한 질문:** 제공된 문서에서 확인할 수 없다고 안내하고, 수치나 사실을 추정하지 않습니다.
- **일부만 답변 가능한 질문:** 확인 가능한 부분은 근거와 함께 답변하고, 확인 불가능한 부분은 별도로 구분합니다.

추가 사실 없이 확인 불가만 안내하는 답변에는 인용을 필수로 요구하지 않습니다. 다만 배경 정보나 수치를 덧붙였다면 해당 내용의 정확성과 근거도 평가합니다.

최종 통과 여부는 사람이 원문과 답변을 대조하여 판단하며, 세 평가 항목을 모두 충족한 경우에만 통과로 기록합니다. Ragas 점수와 LLM Judge의 판정은 문제의 원인을 분석하고 사람의 판단과 비교하는 자료로 활용합니다.

## 3. 평가 프레임워크와 지표 선택 이유

검색 품질과 생성 품질을 나누어 평가할 수 있어 Ragas를 선택했습니다. 골든 데이터로 필요한 근거를 검색했는지 확인하고, 실제 전달한 컨텍스트와 답변으로 생성 품질을 평가합니다.

| 구분 | 지표 | 선택 이유 |
|---|---|---|
| 검색 | Context Precision | 필요한 근거가 검색 결과의 상위에 배치되는지 확인합니다. |
| 검색 | Context Recall | 정답에 필요한 근거를 빠짐없이 검색했는지 확인합니다. |
| 생성 | Faithfulness | 답변의 주장이 실제 전달한 근거로 뒷받침되는지 확인합니다. |
| 생성 | Answer Relevancy | 답변이 질문과 관련되는지 확인합니다. |

수치 계산과 인용, 답변 가능 범위는 규칙 검사와 LLM Judge로 보완합니다. 사람의 검토 결과도 별도로 기록하도록 구성했습니다.


## 4. RAG 구성과 평가 흐름

2주차의 검색·생성 구성을 유지하고, 저장된 답변을 평가하는 파이프라인을 연결했습니다.

| 항목 | 구성 |
|---|---|
| 대상 문서 | 동원파츠 정정 증권신고서 PDF |
| 청킹 | 1,200자, 최대 중첩 200자, 페이지·정정 구간별 분할 |
| 검색 임베딩 | `text-embedding-3-small`, 1,536차원 |
| 검색 방식 | Chroma DB의 임베딩 벡터 검색, cosine 거리 기준 |
| 검색 개수·순서 | 정정 전 상위 3개 → 정정 후 상위 3개, 총 6개 |
| 생성 모델 | `gpt-5.4-mini-2026-03-17` |
| 생성 프롬프트 | 제공된 근거에 따라 답변하고 근거 라벨을 인용하도록 구성했습니다. |
| Ragas 평가 모델 | `gpt-5.4-2026-03-05` |
| LLM Judge 모델 | `gpt-5.4-2026-03-05` |
| Answer Relevancy 평가 임베딩 | `text-embedding-3-large`, 3,072차원 |

평가는 다음 순서로 진행합니다.

1. 골든 데이터셋의 질문 10개를 기존 RAG에 입력합니다. 골든 정답과 평가 기준은 생성 입력에 포함하지 않습니다.
2. 검색 결과, 생성 모델에 실제 전달한 컨텍스트, 최종 답변을 문항별 JSON으로 저장합니다.
3. 저장된 결과에 Ragas 지표, 규칙 검사, LLM Judge를 적용합니다.
4. 문항별 점수와 판정 이유를 저장하고, 전체 결과를 JSON·CSV로 요약합니다.
5. 사람의 검토 결과를 별도로 기록하여 자동 평가 결과와 비교할 수 있도록 구성했습니다.

실행은 `main.py`의 `generate`와 `evaluate` 명령으로 구분하며, 평가할 때는 저장된 답변을 사용합니다.

## 6. 대표 실패 분석

### Q05 — 필요한 세부 근거 누락과 근거 없는 계산

Q05는 연도별 시설자금과 3개년 합계, 2027년 시설자금 중 건축자금을 제외한 금액을 묻는 질문입니다.

| 확인 항목 | 분석 결과 |
|---|---|
| 원문 근거 | PDF 113쪽에 2027년 시설자금 20,920백만원이 있고, 115쪽에 건축자금 9,600백만원이 있습니다. |
| 기대 계산 | 20,920 − 9,600 = 11,320백만원입니다. |
| 검색 결과 | 연도별 시설자금 총액은 검색했지만, 건축자금 9,600백만원의 근거는 검색하지 못했습니다. |
| 실제 전달 컨텍스트 | 시설자금 총괄 내역은 포함됐지만, 건축자금을 분리한 세부 금액은 없었습니다. |
| 실제 답변 | 시설자금 전액을 건축자금으로 간주하여 20,920 − 20,920 = 0으로 계산했습니다. |
| 답변의 모순 | 제외 금액을 0이라고 답한 뒤, 건축자금의 세부 금액은 확인할 수 없다고 설명했습니다. |

검색 단계에서는 계산에 필요한 입력값 하나를 놓쳤고, 생성 단계에서는 그 값을 임의로 가정하여 계산했습니다. 원문으로는 답변 가능한 질문이었지만, 검색한 근거만으로는 제외 금액을 계산할 수 없는 상태였습니다.

Context Recall은 건축자금 근거 누락을 반영해 0.500으로 계산됐습니다. Faithfulness는 제외 금액 0과 해당 계산식을 미지원으로 판정했지만, 나머지 연도별 금액과 합계 등이 근거에 부합해 전체 점수는 0.778이었습니다. LLM Judge는 정확성과 인용 적절성을 실패로 판정했습니다.

우선 개선할 부분은 시설자금 총괄표와 세부표의 근거를 함께 확보하는 검색 방식입니다. 생성 단계에서도 계산 입력값의 근거가 부족하면 확인 가능한 금액까지만 답하고, 부족한 값을 가정해 계산하지 않도록 보완할 필요가 있습니다.

### Q07 — 높은 Faithfulness에도 남는 핵심 환각

Q07은 문서에 없는 실제 최종 청약 경쟁률을 묻는 질문입니다. 답변은 근거에 없는 “6.91대 1”을 제시했지만, Faithfulness는 0.889로 계산됐습니다.

평가기는 경쟁률 주장을 미지원으로 판정했습니다. 그러나 배정물량·청약기간·확인 불가 안내 등 나머지 8개 주장을 지원되는 것으로 판단하여, 전체 9개 중 8개가 인정됐습니다.

이 사례는 핵심 답변이 잘못됐더라도 주변 설명이 근거에 부합하면 Faithfulness가 높게 나올 수 있음을 보여줍니다. 따라서 점수와 함께 어떤 주장이 미지원으로 판정됐는지 확인해야 합니다. 별도 LLM Judge는 이 문항을 실패로 판정했습니다.

README에 기록한 리뷰 결과는 통과 4개, 실패 5개, 보류 1개입니다. LLM Judge와 종합 판정이 일치한 문항은 9개입니다. Q03은 Judge가 통과로 판정했지만, 리뷰에서는 원문에 배정비율 변경 가능성이 남아 있어 답변의 ‘확정’ 표현을 추가 확인할 필요가 있다고 보고 보류했습니다.


## 7. 실행 코드 흐름

(1) **질문 실행** — `main.py generate`에서 골든 데이터셋의 질문 10개를 읽습니다.

(2) **검색·답변 생성** — `rag/pipeline.py`에서 질문을 임베딩하고 Chroma DB를 검색한 뒤, 검색 근거를 생성 모델에 전달합니다.

(3) **실행 결과 저장** — 검색 결과, 실제 전달 컨텍스트, 최종 답변을 문항별 JSON으로 저장합니다.

(4) **자동 평가** — `main.py evaluate`에서 저장된 결과를 읽고, `evaluation/runner.py`를 통해 Ragas·규칙 검사·LLM Judge를 실행합니다.

(5) **평가 결과 저장** — 문항별 점수와 평가 이유를 JSON으로 저장하고, `reporting/summary.py`에서 전체 결과를 JSON·CSV로 요약합니다.
