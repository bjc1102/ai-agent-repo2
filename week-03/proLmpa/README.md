# Week-03: RAG 평가 파이프라인

## 1. 평가 목적과 성공 기준

**평가의 개념적 목적:** LLM Evaluation은 단순히 "답변이 맞았는가"를 확인하는 것을 넘어, 시스템의 어느 레이어—검색(Retrieval)인지 생성(Generation)인지—가 실패를 유발하는지 진단하고, 다음 개선 우선순위를 결정하기 위해 수행한다. 검색이 올바른 청크를 찾아왔는데 생성 단계에서 틀린 것인지, 아니면 검색 자체가 실패한 것인지를 구분해야 올바른 처방이 가능하다.

Week-02에서 구축한 Dense RAG(ChromaDB + paraphrase-multilingual-mpnet-base-v2 + Claude claude-sonnet-4-6)의 품질을 정량적으로 측정하고, 알려진 실패 원인을 진단한다.

**성공 기준:**
- 답변 가능한 질문(Q1, Q2, Q3): ID-based Recall@5 ≥ 0.5, Faithfulness ≥ 0.7
- 답변 불가 질문(Q4): 모델이 올바르게 거절 (answerability_correct = true)
- 부분 답변 가능 질문(Q5): 임플란트 부분 정답, 스케일링 부분 거절

**실제 결과로 본 성공·실패 예시:**

| 케이스 | 검색 결과 | 생성 결과 | 결론 | 사람 판정 |
|--------|-----------|-----------|------|-----------|
| Q1 (성공) | Recall@5=1.00, 정답 청크 Top-1 | Faithfulness=1.00, 근거 조항 명시 | 검색·생성 모두 성공 | pass |
| Q2 (검색 실패) | Recall@5=0.00, 정답 청크 없음 | Faithfulness=0.33, 오거절 | 검색 실패 → 생성도 연쇄 실패 | fail |
| Q4 (생성 미흡) | ground truth 없음 (unanswerable) | 거절은 옳으나 문서 외 추론 추가 | 거절 판단은 올바름, 생성 품질 미흡 | partial |

## 2. 프레임워크·지표 선택 이유

| 지표 | 선택 이유 |
|------|-----------|
| **ID-based Recall@5** | LLM 없이 검색 품질을 직접 측정. 정답 청크가 Top-5에 들어오는지 확인. |
| **Ragas ContextRecall** | 검색된 컨텍스트가 ground truth reference를 얼마나 커버하는지 LLM 판정. |
| **Ragas Faithfulness** | 생성된 답변이 검색된 컨텍스트에 근거하는지 측정 (hallucination 탐지). |
| **Ragas FactualCorrectness** | 답변의 사실적 정확도를 reference와 비교. |
| **Ragas ResponseRelevancy** | 답변이 질문에 얼마나 관련성 있는지 측정. |
| **Answerability binary** | 거절이 필요한 질문에서 모델이 올바르게 거절했는지 키워드 기반 판정. |

**다른 프레임워크와의 비교:**

| 프레임워크 | 주요 지표 | 특징 | 선택 여부 |
|-----------|-----------|------|----------|
| **Ragas** | ContextRecall, Faithfulness, FactualCorrectness, ResponseRelevancy | LangchainLLMWrapper로 Claude 연결 간단, 설치 1단계 | ✅ 선택 |
| TruLens | Groundedness, Answer Relevance, Context Relevance (RAG Triad) | OpenAI API 중심 설계, Claude 연결 추가 설정 필요 | — |
| DeepEval | G-Eval 기반, 커스텀 지표 추가 용이 | 자체 TestCase 클래스 필요, 학습 곡선 있음 | — |
| ARES | Faithfulness, Answer Relevance, Context Relevance | 훈련 데이터 없이 판정 모델 fine-tune 가능, 설정 복잡 | — |

Ragas를 선택한 이유: `LangchainLLMWrapper(ChatAnthropic(...))`로 Claude를 판정 모델로 즉시 연결 가능하고, `EvaluationDataset`→`evaluate()` 한 번의 호출로 복수 지표를 동시 계산할 수 있어 Week-03 범위에서 가장 적합했다.

**한계:** Ragas 판정자로 생성 모델과 동일한 claude-sonnet-4-6을 사용하므로 self-judging bias 위험이 있다.

**실제 발생한 LLM Judge 불일치 사례:**

| 케이스 | 자동 지표 | 사람 판정 | 불일치 원인 추정 |
|--------|-----------|-----------|----------------|
| Q3 ContextRecall=0.00 | 0.00 | partial (1종 500원 맞음) | Ragas 판정자가 ground truth reference("500원 정액")와 검색 컨텍스트를 비교할 때 표현 미스매치로 커버 없다고 판정한 것으로 추정. 의미는 같지만 문자열이 다를 경우 LLM Judge가 false negative를 낼 수 있음. |
| Q1 FactualCorrectness=0.57 | 0.57 | pass (응급환자·보조기기 2개 정답) | 답변에 근거 조항(별표 1 등) 추가 세부정보가 포함됐는데, Ragas가 reference에 없는 주장을 "틀린 클레임"으로 처리해 점수를 낮춘 것으로 추정. 답변이 풍부할수록 오히려 점수가 낮아지는 역설적 패턴. |

## 7. 실패 분석

### Q2 틀니 검색 실패 — 대표 실패 케이스 분석

**1. 원문에 근거가 있었나요?**

chunk_59 하단에 Q48 답변이 명시되어 있음:

```
...A48. 65세 이상 수급권자가 틀니에 대한 의료급여를 입원 또는 외래에서 받은 경우
본인부담률은 1종수급권자는 5%이며, 2종수급권자는 15%입니다.
```

**2. 검색이 그 근거를 찾았나요?**

ID-based Recall@5 = 0.000. 정답 청크(chunk_57~59, p.17)가 Top-5에 단 하나도 없음.
대신 검색된 5개 청크: chunk_62(p.18), chunk_60(p.17), chunk_47(p.14), chunk_56(p.16), chunk_33(p.11)

**원인 1 — Q48 답변이 chunk_59 끝에 위치 (Q&A 분리 확인)**

`inspect_chunks.py` 로 확인한 chunk_59 전문:
```
 경우에도 본인일부부담금이 면제됩니다.
※ 관련근거 : 「요양급여비용 청구방법...」(고시 제2021-85호)
Q47. 의료급여 선별급여 본인부담은 건강보험 선별급여 본인부담과 다른가요?
A47. 건강보험과 동일한 본인부담률을 적용받습니다.
Q48. 65세 이상 틀니 진료 시 본인부담률은 어떻게 되나요?
A48. 65세 이상 수급권자가 틀니에 대한 의료급여를 입원 또는 외래에서 받은 경우
본인부담률은 1종수급권자는 5%이며, 2종수급권자는 15%입니다.
```

chunk_59(452자)는 Q46 overflow → Q47 → Q48 순으로 구성된다.
Q48 답변은 청크 하단 ~150자에만 등장하고, 나머지 ~300자는 Q46/Q47 내용이다.
임베딩은 청크 전체를 평균화하므로 Q48 신호가 희석되어 "틀니 본인부담률" 쿼리와의 유사도가 낮아진다.

**원인 2 — 단편 노이즈 청크 4개가 Top-5를 오염**

| 청크 | 페이지 | 길이 | 실제 내용 |
|------|--------|------|-----------|
| chunk_60 | 17 | ~40자 | `별표1] 제1호라목, 제2호마목\n32 2024 알기 쉬운 의료급여제도 Ⅱ. 자주하는 질문 33` |
| chunk_47 | 14 | 39자 | `업안내」\n26 2024 알기 쉬운 의료급여제도 II. 자주하는 질문 27` |
| chunk_56 | 16 | 51자 | `정액수가 관련 질의·답변\n30 2024 알기 쉬운...` |
| chunk_33 | 11 | 52자 | `법 시행규칙」제3조제1항제14호\n20 2024 알기 쉬운...` |

이 청크들은 PDF 다단 레이아웃에서 발생한 페이지 번호·헤더·꼬릿말 잔재다. 실질 내용이 없음에도 Top-5에 포함되어 검색 슬롯 4개를 낭비한다. 결과적으로 Top-5 중 실제 내용이 있는 청크는 chunk_62 단 하나뿐이다.

특히 chunk_60은 정답 청크(chunk_59)와 **동일 페이지(p.17)**임에도 불구하고 노이즈 텍스트만으로 구성되어 있어, 같은 페이지의 실제 Q&A 청크들(chunk_57~59)보다 높게 랭크됐다.

**원인 3 — chunk_57·58이 Top-5에 없는 이유**

chunk_57·58은 chunk_59와 동일 페이지(p.17)의 연속 청크(100자 오버랩)이지만, Q48의 핵심 내용("틀니", "1종 5%", "2종 15%")은 chunk_59에만 등장한다. chunk_57·58은 그 앞에 위치한 다른 Q&A들(Q44~Q46 등)로 채워져 있어 "틀니 본인부담률" 쿼리와의 임베딩 유사도가 낮다. 고정 크기 청킹이 Q&A 경계를 무시하고 자른 결과, 정답 키워드가 chunk_59 한 곳에 집중되고 chunk_57·58은 오히려 무관한 주제로 구성된다.

**원인 4 — chunk_62가 "틀니" 키워드를 포함하지만 오답 맥락**

chunk_62(p.18)는 "65세 이상 치과 틀니 및 임플란트 비용...지급에서 제외됩니다"라는 문장을 포함하여 최상위 검색됐다. 그러나 이는 본인부담률 표가 아닌 **보상제·상한제 제외 항목 목록**이다. 키워드는 일치하지만 의미적 맥락이 다른 사례.

**결론:** 고정 크기 청킹 → Q48이 chunk_59 끝부분에만 위치 → 임베딩 희석, chunk_57·58은 무관 Q&A로 채워짐, 동시에 노이즈 청크 4개가 슬롯을 차지, 유일하게 "틀니"를 포함한 chunk_62는 오답 맥락 → Recall@5 = 0. Top-5 중 정답과 관련 있는 청크가 사실상 한 개도 없는 완전한 검색 실패.

**3. 생성 모델은 전달된 근거를 사용해 충분히 답했나요?**

검색 실패로 인해 정답 청크가 전달되지 않았으므로, 모델은 근거 없이 오거절했다. 이는 생성 단계 자체의 실패라기보다 검색 실패의 2차 결과다.

**4. 답변 가능 여부를 올바르게 판단했나요?**

오판. 질문은 answerable임에도 모델이 "문서에서 찾을 수 없다"고 거절했다 (Answerability = incorrect).
