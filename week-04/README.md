## 1. 기존 평가 검토와 보완

기존 자료는 6쪽·29청크였고 단일 근거 질문이 많았다. 높은 Recall이 문서와 문항의 작은 범위에 영향을 받았을 수 있어 문서를 3개로 늘리고 비교 질문을 추가했다.

- **연도 표현:** 기존 `’30년`은 사실 오류와 별개로 표현 명확성이 부족하다고 판단했다. 4자리 연도 명시와 축약 연도 사용을 별도로 검사했다.
- **확인 불가 안내:** 기존 규칙이 `자료에 나와 있지 않습니다`를 놓쳤다. 인정 표현을 보완하고 부정의 부정 등 예문으로 검사했다.
- **근거와 정답의 구분:** Recall은 필요한 근거의 포함 여부를 측정하고, 필수요소는 답변의 값·표현을 검사한다. 어느 지표도 단독으로 전체 정답률을 의미하지 않는다.
- **동일 기준 적용:** 평가 기준을 기법 적용 전에 고정하고 세 구성에 동일하게 적용했다. 기대 답변과 평가 라벨은 검색 문서나 생성 입력에 넣지 않았다.
- **기존 평가 재검토:** 기존 E3/E5 답변의 규칙 재검사 기록은 `week03_evaluation_audit.json`에 남겼다. 문서·질문이 달라진 이번 비교에서는 확장한 기준선을 새로 실행했다.

실행 후에도 Q5 기준선의 `제시되지 않았습니다`라는 정상 표현을 놓치는 규칙의 잔여 결함을 발견했다. 이번 제출에서는 점수를 유리하게 바꾸지 않고 원 점수와 판정 차이를 함께 기록했다.

## 3. 방법 조사와 선택

다른 후보로 메타데이터 필터링, 질문 재작성·멀티쿼리, 부모 문서 확장, HyDE, 문맥 보강 검색을 검토했다. 기준선은 이미 벡터+BM25 검색을 사용하므로 하이브리드를 새로운 기법으로 세지 않았다.

### 개선 A: 재순위화

기존 검색이 찾은 후보를 질문-문서 쌍으로 다시 평가하고 순서를 바꾼다. 유사한 사업·연도의 자료 중 더 적합한 근거를 앞으로 올릴 것으로 예상했다. 별도 모델의 메모리·처리 시간이 필요하며, 재정렬이 틀릴 수 있고 최초 후보에 없는 근거를 되찾지는 못한다.

`BAAI/bge-reranker-v2-m3`를 CPU에서 사용했다. 후보마다 점수를 매긴 뒤 기준선과 같은 컨텍스트 한도를 적용했다.

### 개선 B: 질문 분해

Gemma가 원 질문을 검색용 하위 질문 최대 3개로 나눈다. 원 질문도 유지해 최대 4번 검색하고 근거를 통합한 뒤, 원 질문에 대한 최종 답변을 한 번 생성한다. 복수 문서 질문에서 한쪽 근거만 찾는 문제를 줄일 것으로 예상했다.

분해용 모델 호출과 검색이 추가된다. 분해 과정에서 사업명·연도·요구사항이 훼손되거나 넓어진 후보가 제한된 컨텍스트를 차지할 수 있다. 중간 답변은 생성하지 않으며 B에 A를 함께 적용하지 않는다.

선택 근거는 검색 후 후보 순서와 검색 전 질문이라는 서로 다른 단계를 독립적으로 비교할 수 있다는 점이다.

## 6. 평가 기준

- **근거 Recall:** 필요한 근거 그룹이 검색 후보와 실제 전달 컨텍스트에 포함됐는지 Ragas IDBasedContextRecall로 확인했다. 답변 불가 문항에는 적용하지 않는다. 근거가 포함됐다는 뜻이며 정답이나 검색 정밀도를 보증하지 않는다.
- **필수요소 포함률:** 값·표현과 사업명 연결을 규칙으로 검사한다. 모든 의미 오류·누락·불필요한 주장을 판별하지는 못한다.
- **연도 명확성:** 필요한 4자리 연도 표기와 축약 연도 사용을 확인한다. 연도 사실관계 검사와는 다르다.
- **Faithfulness:** 같은 Gemma를 Judge로 사용해 실제 답변의 사실 주장이 실제 전달 문서로 지지되는지 평가했다. 기대 답변과 비교하는 정답률이 아니다. 순수 확인 불가 안내에는 적용 불가다.
- **사람 판정:** 모든 요구를 근거대로 해결하면 충족, 일부 누락·불명확성·부정확한 여분 설명은 부분 충족, 핵심 단위·사업 연결 오류는 실패로 판단했다. 판정은 사용자 요청에 따른 작성 대행으로 기록한다.

## 8. 대표 사례·성공 문항 회귀 확인·우선 개선

### 대표 실패: Q1 질문 분해

**원문 근거:** D2026 PDF 1쪽에는 추가 후보지 6곳·7.67만호, 기존 3곳·2.72만호, 2030년 내 착공 목표가 있다.

**검색과 전달:** 필요한 근거 그룹 3/3을 찾았고 실제 생성 컨텍스트에도 포함됐다. 따라서 이번 실패를 최초 검색 누락으로 보기는 어렵다.

**최종 답변:** `이번에 추가한 후보지는 7.67만호이며, 공급 규모는 기존 발표분과 구분하여 알려주지 않습니다`라고 답했다. 개소와 호수를 혼동하고, 문서로 답할 수 있는 기존·추가 물량 구분을 해결하지 못했다. 착공 목표 일부를 맞혔어도 핵심 의미 오류가 있어 실패로 판정했다.

**자동 평가와 차이:** 필수요소 0.75는 수치·목표·연도 표현의 존재를 셌지만 그 수치가 어떤 요구에 연결됐는지는 충분히 검사하지 못했다. Judge는 원문에서 기존·추가 물량을 구분하지 않는다고 잘못 해석해 Faithfulness 1.00을 부여했다.

**우선 개선:** 수치의 존재뿐 아니라 사업·단위·역할의 연결과 질문의 각 요구사항 충족을 점검해야 한다. 컨텍스트 순서·방해 자료·생성 모델 능력 중 무엇이 원인인지 각각의 인과 효과는 이 단일 실행만으로 확정하지 않는다.

### 성공 항목과 회귀

- **Q2:** 세 구성 모두 2024년 고양대곡 역세권 본문 0.9만호와 2026년 확장 4천호를 구분했다. 기준선도 이미 복수 문서 질문을 해결했다.
- **Q3:** 기준선·질문 분해는 정확했지만 재순위화는 다른 사업을 동일시했다. 필요한 근거는 전달됐으므로 검색 순서 변경이 항상 답변 개선으로 연결되지는 않았다.
- **Q4:** 기준선·질문 분해는 가격을 만들지 않았다. 재순위화는 자료 내용의 범위를 과도하게 한정하는 여분 문장을 추가했다.
- **Q5:** 기준선·질문 분해는 확인 가능한 공급량과 확인 불가 입주일을 구분했다. 재순위화는 입주일 안내를 누락했다.

### 평가 시스템에서 확인한 문제

1. **Q5 기준선:** `제시되지 않았습니다`는 올바른 표현이지만 규칙이 놓쳐 0.67이 됐다. 생성 답변의 불충분함과 평가 규칙 결함을 구분했다.
2. **Q5 질문 분해:** Judge는 확인 불가 안내를 사실 주장으로 추출한 뒤 자료에 입주일이 없다는 이유로 0을 줬다. 이로 인한 0.50을 실제 답변의 품질 저하로 그대로 해석하지 않았다.
3. **Q5 재순위화:** Judge가 추출한 주장을 변경해 반환해 평가 오류가 됐다. 평가 도구 오류와 답변의 입주일 누락은 별개다.
4. **Q3 재순위화:** Judge는 `구리건원(구리토평2)`이라는 잘못된 동일시도 통과시켰다.
5. **Q1 연도:** `2030년`이 없어서가 아니라 `2030년`과 `‘30년`을 병용해 연도 명확성 0이 됐다. 사실 오류와 표현 명확성을 분리했다.

후속 평가에서는 확인 불가 동의 표현, 수치-대상-단위 연결, Judge의 정보 부족 안내 취급을 보완해야 한다. 기준을 바꾸면 세 구성의 저장 답변에 동일하게 재적용한다. 이번 보고서의 자동 점수는 사후 교체하지 않았다.

## 9. 기법 적용 여부 판단

- **기준선: 유지.** Q1의 공급량 누락은 남지만 Q2~Q5를 충족했고 가장 짧은 평균 시간을 보였다.
- **재순위화: 현재 구성에서는 제거.** 평균 시간이 기준선 약 3.15배였으나 품질 이득 없이 Q3 사업 동일시·Q5 누락 등이 발생했다. 현재 문서·후보 수·모델·배치 조건에서 추가 지연을 감수할 이득을 확인하지 못했다.
- **질문 분해: 수정 후 재검증.** 평균 시간은 약 8.0% 늘고 chat 호출은 2배, 검색은 3.6배였다. 기준선도 해결한 문항의 실질 개선 없이 Q1은 악화됐다. 실제 근거 누락이 있는 복수 문서 질문에 조건부 적용하는 방식과 하위 질문의 요구사항 보존을 검토한다.

문항 5개·각 1회이므로 통계적 우위나 일반적인 정확도를 주장하지 않는다. 재순위화는 CPU, Gemma는 GPU에서 실행한 배치 조건에도 지연이 영향을 받는다. 근거 Recall은 관련 청크의 존재만 측정하며 정밀도나 전체 답변 품질을 보증하지 않는다.
